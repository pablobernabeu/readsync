# Changelog

## Unreleased

Each passage now runs as one tracker trial. The trial runs the drift check while the tracker is idle, records the passage and asks the questions. Under the information-seeking regime, it also shows the questions before the drift check. The EyeLink backend opens and closes a trial in the data file, and each trial names an EyeLink Data Viewer interest-area set holding the passage's word boxes, written beside the local copy of the data file and named after it and the trial's position in the session. In 0.1.0, recording started once before the first passage, and a drift check ran before every passage, the first included, while the tracker was recording. pylink's drift check is meant to run while the tracker is idle, so, with an EyeLink, the passages would probably not have been recorded. A test now runs the backend's connection, trial, recording and closing calls in pylink's dummy mode, and the `eyelink` extra installs SR Research's pylink from PyPI. Calibration, the drift check and recording still have to be validated with a tracker.

New features include `MultiMarkerSink`, a CSV export of the word interest areas and `recover_events` for logs damaged by a crash. `MultiMarkerSink` passes each marker to several sinks in turn, for example an `EyeLinkMarkerSink` and an `LSLMarkerSink`. `EventLog` gains `sync` and `head`. Session events carry a session identifier, the planned passages, the settings that the tracker and the presenter report (the EyeLink and PsychoPy backends do), a completion status and the session clock, and the quality report shows the status and the number of planned passages. Nested and overlapping regions each get their own events, region exits record whether the gaze moved or the passage ended, and word and region events carry the tracker time of the sample that produced them. `EyeLinkTracker` takes a calibration graphics factory and an eye to track, and it reports the status of its last drift check. `PsychoPyPresenter` exposes its window and checks the drawn character width against the layout, and `LSLMarkerSink` can wait for a recorder. For the webcam, `MediaPipeIrisEstimator` accepts the head-aware model and gives zero confidence during blinks and when the head is more than `max_pose_drift_deg` (12° by default) beyond the calibrated head-pose range, and `WebcamTracker` marks estimates off the screen invalid. The browser demo's CSV gains a `detail` column, quotes cells that contain commas, quotation marks or line breaks and records each calibration and the passages' word boxes.

Several defects are fixed. The quality report measured sample loss only between the first and last samples of a passage, so data missing at its start or end, or a passage with no data, went unreported. PsychoPy question and prompt screens vanished after one frame. The Lab Streaming Layer stream did not exist until the first marker was sent. Overlapping offline guards could leave a session unguarded or a process permanently offline. A region nested inside an earlier-listed region was never entered, and a nested region listed before the region enclosing it split the visit to the enclosing region in two. `angular_error` overstated errors away from the centre of the screen. The webcam estimator in a session ignored head pose and blinks, `OpenCVCamera` passed frames to MediaPipe in BGR order, and `WebcamTracker` delivered about 22 samples a second instead of 30 on a 60 Hz display, because a display frame that arrived even slightly early delayed the sample to the next display frame. In browsers that offer `requestVideoFrameCallback`, the browser demo now samples once per camera frame instead of once per display refresh. It also no longer decomposes the transposed head-pose matrix. The webcam demo restarted its clock on every recalibration. EDF names with non-ASCII letters or a leading underscore were accepted, and the stimulus build gave words missing from the frequency source a Zipf value of 0.

Some behaviour has changed in ways that can break existing scripts or alter data. `PsychoPyPresenter` opens its window with `useRetina` off and raises an error when the window opens at a size other than `size`, so set `size` to the display's resolution. In 0.1.0, such a window drew words away from their interest areas. A session refuses a log that already holds records, a tracker whose frame differs from the presenter's window and passages that do not fit the window. These checks run before the tracker connects, and every cleanup step runs even if an earlier one fails. `load_stimulus_set` and `load_passages` refuse repeated ids, and `load_passages`, like `load_stimulus_set` before it, refuses ids that are empty or contain whitespace or `=`. `load_stimulus_set` also refuses target indices that are not integers or do not match the text, and it refuses frequency indices outside the passage. `interest_areas` refuses a word longer than a line. `angular_error` and `mean_angular_error` now need `eye_px`, the screen point straight ahead of the eye. The calibration outcome is logged after every drift check that was aborted or escalated, where 0.1.0 logged it only when the tracker's calibration message changed. `OpenCVCamera` returns RGB frames by default, where 0.1.0 returned OpenCV's BGR order, so a script whose estimator converted frames itself should remove that conversion or create the camera as `OpenCVCamera(rgb=False)`. Response times come from the keyboard's timestamps. For the EyeLink, `tracker_t` is now the sample's time on the Host PC clock, so it matches the EDF timestamps. Marker messages, on the EyeLink and on Lab Streaming Layer, now list their identifiers first, and EyeLink messages are capped at 128 characters. `pseudonymise` now puts an identifier in Unicode NFC form and strips surrounding whitespace before hashing, so any identifier with surrounding whitespace or not already in NFC form gets a different code from the one 0.1.0 gave, and an identifier made only of whitespace is refused. In the browser demo, gaze is marked invalid and the page asks for a recalibration when the window moves or when its width or height changes by more than 3%, where 0.1.0 allowed 10% and did not check for moves, and a recalibration closes the interrupted sentence with a `passage_offset` event. The `stimuli` extra requires wordfreq 3.1.1 or later and below 4, the `webcam` extra excludes the two MediaPipe releases that omit OpenCV, and the documentation has been corrected to match the code.

## 0.1.0 (2026-08-26)

First public release. The data-handling core runs and is tested with no research hardware: pseudonymisation, encryption at rest, the tamper-evident hash-chained event log, the offline `NetworkGuard`, word and layer-typed region interest areas, comprehension questions with scored responses, session control, a per-session data-quality report and CSV export of the event log. The release also includes a PsychoPy presenter, an EyeLink backend over pylink, webcam gaze estimation for a laptop and a browser demo of the webcam model at https://interlexis.web.app.
