# Interlexis webcam reading demo (browser)

A client-side webcam gaze demo for reading, hosted at https://interlexis.web.app. It runs the gaze features and the head-aware calibration model of readsync's webcam module, ported to JavaScript, entirely in the browser. The model arithmetic and the head-pose extraction are checked against a fixture generated by the Python code.

## Privacy and security

Camera frames are processed in the browser by MediaPipe FaceLandmarker, and the gaze estimates, the calibration and the event log stay on the device. Data leave the page only when the reader clicks Download CSV, which saves `interlexis-session.csv` locally. The CSV is unencrypted and carries no participant code, unlike the desktop toolkit's session log.

The MediaPipe runtime, the model and their licence are vendored by `scripts/fetch-assets.mjs` and pinned by SHA-256 in `scripts/assets-manifest.mjs`, so a substituted download can be neither vendored nor deployed. The stimuli are a committed copy of `stimuli/controlled_freq_en.json`, which a test keeps identical to the source. Everything is served from the site's own origin.

`firebase.json` sets the response headers. The Content-Security-Policy restricts every source to the site's own origin, adding only what the pipeline needs: `'wasm-unsafe-eval'` for MediaPipe's WebAssembly, and `blob:` and `data:` for the worker, images and media that the browser creates locally. `connect-src` allows only the site's own origin, and the site has no server-side endpoint, so the page's scripts cannot send data to another host by fetch, XHR or WebSocket. The Permissions-Policy allows the camera for this origin and disables the microphone and geolocation. Framing is refused, and the site uses no analytics, cookies or trackers. Firebase Hosting and its emulator apply these headers, whereas another static server would not.

## What it does

The page loads the model and the stimuli before asking for camera access, so the permission prompt appears only once the page is ready. It then calibrates on a 3 by 3 grid of dots at each of two head positions, so that the model can learn how head pose shifts the iris feature. It reports a cross-validated error, holding out each target at both positions, flags errors above 6% of the screen and offers a redo. The webcam self-view is hidden while the dots are shown, so it cannot cover the corner targets.

The reading stage shows sentences from the controlled frequency set with a live gaze dot and a box round the word under it. It presents one member of each matched pair, alternating condition across pairs, so the reader never sees the same sentence frame twice (`public/js/stimuli.js`). The assignment is the same in every session, so data from the demo cannot separate the frequency contrast from the sentences. Every stage can be operated by button as well as by keyboard, so the demo also works on touch devices.

At the end, the reader can download the in-browser event log as a CSV with the columns `type,t,passage,word,x,y,valid,detail` and the event types `session_start`, `calibration`, `passage_onset`, `areas`, `gaze`, `word_enter`, `passage_offset`, `recalibrate` and `session_end`. A calibration event records the cross-validated error, whether it was accepted, the window size and the device pixel ratio. An `areas` event records each word's box in window pixels as JSON, so gaze can be assigned to words again after the session. All times share one session clock.

Gaze is estimated once per new video frame in browsers that offer `requestVideoFrameCallback`, and once per display refresh in others. While reading, the dot turns amber and asks for a recalibration once the head turns more than 12° beyond the range seen during calibration, or once the window moves or its width or height changes by more than 3%. During blinks, the last gaze position is held. A recalibration closes the interrupted sentence in the log, and reading resumes at that sentence.

## Limits

Webcam gaze is much coarser and noisier than infrared eye-tracking, and the demo's accuracy has not been measured against a reference tracker. Word-level reading measures need a research-grade eye-tracker.

## Run it locally

```bash
cd web-demo
node scripts/fetch-assets.mjs        # vendor the MediaPipe runtime, model and licence (once)
npm test                             # gaze-maths checks, including the fixture from the Python code
firebase emulators:start --only hosting   # or: firebase serve --only hosting
```

Then open the printed `http://localhost` address. `localhost` is a secure context, so the browser allows camera access there. Another static server will run the demo if it serves `.mjs` as JavaScript and `.wasm` as `application/wasm`, but only the Firebase emulator and `firebase serve` apply the security headers.

## Deploy to Firebase Hosting

The site is static. It has no Cloud Functions, database or server-side storage.

```bash
cd web-demo
node scripts/fetch-assets.mjs        # make sure the vendored assets are present
firebase deploy --only hosting
```

A predeploy hook, `scripts/check-assets.mjs`, fails the deploy if any vendored file is missing or does not match its pinned SHA-256. Those files are gitignored, so a fresh clone would otherwise deploy a site that cannot start. HTML, scripts and stimuli are served with `Cache-Control: no-cache`, so a redeploy shows up on a normal reload. The vendored runtime and model are version-pinned and cached for a year.

## Layout

```
web-demo/
  public/
    index.html, styles.css, favicon.svg
    js/linalg.js      linear algebra (port of readsync.webcam._linalg)
    js/gaze.js        gaze features and model (port of readsync.webcam.tracker and gaze)
    js/stimuli.js     demo stimulus selection (one member per pair)
    js/app.js         camera, calibration and reading
    stimuli/          copy of the controlled frequency set
    vendor/, models/  vendored MediaPipe runtime and model (fetched, gitignored)
  scripts/assets-manifest.mjs    pinned versions and SHA-256 hashes of the vendored assets
  scripts/fetch-assets.mjs       vendors the runtime, model and licence, verifying each hash
  scripts/check-assets.mjs       predeploy check of the vendored assets
  test/gaze.test.mjs             Node tests of the gaze maths
  test/make_parity_fixture.py    writes the parity fixture from the Python code
  test/fixtures/parity.json      the parity fixture
  firebase.json, .firebaserc, package.json
```

## Versions

The MediaPipe runtime is pinned to tasks-vision 0.10.35 with a SHA-256 for each file in `scripts/assets-manifest.mjs`. The Python `webcam` extra accepts any mediapipe 0.10 release, so keep both on the same series when bumping either, and refresh the hashes from a download you have inspected. The runtime and the model are licensed under Apache 2.0, and their licence is vendored and served at `vendor/LICENSE`. If a future MediaPipe build reports a blocked `eval`, widen `script-src` for that build only. Do not add a `connect-src` host, since that directive is what stops fetch, XHR, WebSocket and beacon requests to other hosts. The policy does not govern top-level navigation, and any same-origin endpoint added to the site later would be reachable, so keep the demo on a static site of its own.
